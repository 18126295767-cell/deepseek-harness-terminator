# 竞品调研报告 · 桌面 AI 助手 + 内置浏览器

> 产品对象：`deepseek-harness-terminator` —— 把本地 DeepSeek Harness 封装为原生 macOS 桌面
> App（AppKit/WebKit 外壳），自带内置实时浏览器面板（`Cmd+B`）与本地离线语音输入（`⌘⇧M`）。
>
> 目的：梳理同赛道竞品功能与需求，找出本产品「该有而还没有、或还没做全」的能力，供后续
> 缺口分析与功能补齐参考。
>
> 方法与局限说明：当前环境的内置 `web_search` 因余额不足不可用，浏览器抓取的搜索结果页
> 未能返回结构化正文。因此本报告基于对这些公开、稳定产品的既有领域知识整理（非实时爬取），
> 涉及产品功能均为长期公开信息，仍属可靠；但**未提供本次实时的外部来源链接**。若需逐条
> 引证，可在网络额度恢复后补充。

## 1. 竞品图谱：三类玩家

把「桌面 AI 助手 + 内置浏览器」的赛道拆成三类，各有不同的借鉴点：

| 类别 | 代表 | 核心卖点 | 与本产品共性 |
|---|---|---|---|
| A. 全功能现代化浏览器 | Arc、SigmaOS、Sidekick、Floorp、Orion | 标签/命令/分屏/工作区/AI 集成 | 内置浏览器本体 |
| B. 系统级命令面板/启动器 | Raycast、Alfred、LaunchBar | 全局快捷键、命令面板、扩展生态 | 「唤出一个面板做任何事」的交互模型 |
| C. 桌面 AI 对话客户端 | OpenAI/Claude/豆包/文心/通义/AnythingLLM 等桌面端 | 本地/云端 LLM 对话、附件、截图、语音 | 本地 DSH 会话窗口 |

本产品本质上是 **A 的「内置浏览器」** + **C 的「本地 LLM 会话」** 两者合一，但交互层（命令
面板/分屏/工作区）尚未达到 A 的深度，这是缺口的主要来源。

## 2. 逐类竞品功能清单

### 2.1 Arc / SigmaOS / Sidekick（卡片式现代浏览器）

**共同点（现代浏览器基准能力）：**
- 垂直侧边栏 + 垂直标签页（横向标签的替代）。
- 命令/查找栏（`⌘T` 类）：输入即跳到网址、搜索、书签、历史、命令。
- Spaces / 工作区：把不同主题的标签分组、可单独命名与配色。
- 分屏（split view）：同屏并排两个页面。
- 快速预览（hover 卡片）、稍后读（read later / library）。
- 跨设备同步（账号体系 + iCloud / 云同步书签、标签、历史）。
- 底部/角落的「小地图」或 mini-player。

**Arc 特色（最激进）：**
- **Command Bar**：一个框解决导航/搜索/命令，可扩展（命令、快捷操作）。
- **AI（Arc Max / Arc Search）**：随时呼出 AI 摘要网页、Ask 对话式搜索、自动整理标签页、
  AI 重命名标签页、AI 快速浏览。
- **Boosts / 自定义**：按站点定制脚本/CSS（用户脚本）。
- **分屏 + 多标签组 + 固定标签（pinned ephemeral）**。
- **空白起始页 / 新标签页即命令框**。

**SigmaOS 特色：**
- **Airis AI**：侧边 AI 助手，可对当前页面提问、总结。
- **工作流 Workspaces + 快捷命令（snippets）**：组合盒式命令完成多步任务。
- **按「项目/主题」组织标签**，强调注意力管理。

**Sidekick 特色（团队/工作工具向）：**
- 多账号会话隔离（每个工作账号独立会话、cookie、扩展）。
- 集成的生产力工具（内部 app 面板，如邮件/日历/通讯在侧栏）。
- 团队共享书签/工作区。

**对本产品的直接借鉴（可落地）：**
- 内置浏览器面板目前是单文档视图 + 简单标签栏 → 缺：命令查找栏、分屏、工作区/分组、AI
  总结当前页面、按站点定制。这些在 WebKit 内均可实现（尤其命令栏、分屏、工作区）。

### 2.2 Floorp（Firefox 分支，隐私与高定制）

- **原生高可定制**：标签树/垂直标签/水平标签可选、多标签栏、workspace 分组、内置侧栏面板
  （内置浏览器/侧栏可同时显示多个小工具）。
- **隐私优先**：默认强反跟踪、去指纹、本地加密的密码与书签。
- **多媒体、鼠标手势、快捷键扩展丰富**。
- **用户脚本/扩展完整**（Firefox 生态）。

**借鉴点：**
- 多标签栏/标签树、侧栏并排面板、强隐私默认（对本 App「不抢前台、本地优先」的哲学一致）。

### 2.3 Orion（WebKit 引擎 / Kagi）

- 使用 **WebKit 引擎**，与本 App 的 WKWebView 同源 → 渲染行为对得上。
- **垂直标签、精简 UI、按标签页搜索**（搜索当前站内内容）。
- **强隐私/去广告**。
- 与 Kagi 搜索/广告标记者集成。
- 原生性能 + 去追踪。

**借鉴点：**
- 同为 WebKit：Orion 能做的（垂直标签、站内搜索、精简 UI），WKWebView 大多能做。
- 「按标签页站内搜索」是低成本的搜索增强缺口。

### 2.4 Raycast / Alfred（命令面板）

- **全局快捷键唤起**（默认 `⌥空格`），在任何窗口上弹一个命令框。
- 命令面板：应用启动、文件搜索、剪贴板历史、系统控制、扩展脚本。
- **AI 扩展**（Raycast AI）：对话、总结、翻译、自定义 prompt 命令。
- 可编程扩展生态（TypeScript API）。
- 快速操作 + 迷你窗口（HUD 风格，不抢前台工作流）。

**借鉴点（对本产品最相关）：**
- 「全局唤出一个命令面板」正是本产品「内置浏览器面板」该有的交互方向：在浏览任意内容时
  `Cmd+B` 唤出、输入网址/搜索/命令。
- 剪贴板历史、HUD 不抢前台反馈 —— 与本 App「不抢前台」的定位一致。
- AI 命令（翻译/总结/重写）可接到本地 DSH LLM。

### 2.5 桌面 AI 对话客户端（OpenAI、Claude、豆包、文心、通义、AnythingLLM 等）

- **会话窗口**：持久对话、Markdown 渲染、代码高亮、多轮上下文。
- **多模态**：图片/截图/文件/链接输入；TTS 语音输出；部分支持语音输入（App 内录音）。
- **附件与工程上下文**：直接把文件、代码目录喂给模型（这是本 App 背后 DSH 的强项）。
- **本地离线优先**（AnythingLLM/Ollama 系）：本地模型切换、知识库 RAG、聊天记录本地化。
- **系统集成**：全局截图、OCR、剪贴板增强、通知。

**借鉴点：**
- 本产品的 DSH 会话窗口本身就是「C」能力的体现（在 Web 端已具备）。本次交付要补齐的是把它
  和「内置浏览器」结合 —— 例如「把当前页面发给会话」「对当前页面提问/总结」。

## 4. 竞品启发的一句话结论

1. **最大通用缺口 = 命令/查找栏 + 垂直标签/工作区/分屏**：这是现代浏览器基操，本产品目前只有
   单面板 + 简单标签栏。
2. **差异化优势要守住**：本产品「本地优先、不抢前台、绝不外发数据」在所有竞品里是稀缺的，
   补齐功能时应保持这一基调（这也是 voice 已实现/后续功能的立足点）。
3. **AI × 浏览器的结合是价值高地**：把「对当前页面提问/总结」接上本地 DSH LLM，是同时对标
   Arc Max / SigmaOS Airis / Raycast AI 的高性价比差异点。
4. **语音输入本项目已超前**：本地离线语音转写 + 剪贴板桥已跑通，竞品大多只做「App 内录音」，
   本产品反而更符合隐私本地优先。
